## 3. Что MERIDIAN берёт у каждой (жемчужины переноса)

### 3.1 У info1: оператор ↔ (из метрики — в действие)

info1 объявляет связывание РАВНОПРАВНЫМ третьим оператором наряду с ⇑/⇓. У MERIDIAN связность — только метрика (coh) и стрелка в p56.

**Верифицируемый структурный конфликт** (сильнейшая находка всего разбора): в docs/12 гейт **g=(Δlen>0)?coh:0** не оставляет связующему ходу никакого слота — ход «создать связь, не добавляя слова» имеет Δlen=0 ⇒ g=0. «Равноправие ↔» требует правки формулы, а не трактовки. Точность формулировки: формула не «убивает» связующий ход — ей **нечего** оценивать, пока в движке нет субстрата рёбер (в p32/p53 связность — среднее по соседям, множества рёбер как объекта нет).

**Перенос — строго в два шага (p71):**
1. Построить субстрат рёбер: перекрёстные связи фраз/тем в p53–p56 (пары тем p56 — готовый донор структуры).
2. Ввести g_link = ΔI/(ΔI+1) при I = объём×связность для ходов Δlen=0 с новым ребром; редукционный гейт Δlen<0 — по канонической формулировке §3.3 (единой для всего документа); добавить N-аналог для рёбер — повторное связывание тех же тем даёт 0, иначе застой мимикрирует под связывание.

Пример: рой собрал «река несёт лодку» и «время несёт память»; ↔-ход агента связывает темы «река↔время» (метафорический мост) — сейчас этот ход невыразим и невознаграждаем; после правки он даёт g_link>0 при первом связывании и 0 при повторном.

**Дополнительно у info1:** пара (λ̄, Var λ_t) на панель здоровья вместо DB (см. §5), коридорная форма метрик (диапазон вместо максимума) и калибровочный материал 38 циклов — с ограничениями статуса (§5, §8 п.3).

### 3.2 У data7: направленная дистанция и портфель оптимизаторов

**Прочное ролевое соответствие, верифицированное кодом с обеих сторон:** p55-text-evolution.html содержит случайный pair-swap, ошибочно подписанный «2-opt», настоящий отжиг accept(ΔJ,T) и фильтр рационализации с логом «I < (1−ε)·I»; dissertation_optimizer.py data7 содержит направленную дистанцию (_logical_distance: 0.0 если глава-пререквизит, 1.0 в обратную сторону) и настоящий 2-opt. Задача одна — упорядочение элементов по стоимости переходов, но реализации не тождественны.

**Переносы:**
- **Проверенные оптимизаторы → p55:** жадная инициализация, 2-opt и отжиг. Генетику и ДП не переносить как существующий код без отдельной реализации и теста: в проверенном `optimize()` их нет. Дисциплина сравнительного baseline полезна как требование, но числа data7 «40–53% снижения нагрузки» остаются self-reported без приложенного независимого протокола.
- **Асимметризация связности:** направленная d(i→j)=1/(coh+ε)·penalty(пререквизит j не введён до i) — закрывает реальную дырку: порядок лестницы docs/14 (число→формула→теорема→слово) направлен, симметричный coh этого не видит. Делать ПОСЛЕ p69 (замены coh на semantic_sim), иначе направленный шум поверх симметричного.
- **IC/NS как гейты роя p51–p54:** IC — «⇑ не теряет тем нижнего яруса» (иерархия слово→фраза→абзац→рассказ), NS — новизна порождаемой фразы относительно уже собранного корпуса p56. Конкретные числа порогов не переносить: в коде data7 стоит дефолт 0.6 без следов калибровки.

### 3.3 У data7: Rationalizer — «сжатие без гибели» (двуслойный перенос)

**Слой теории (data7 → MERIDIAN).** Формула min K(K′) при I(K,K′)≥(1−ε)·I(K), CC=0 уточняет тезис ядра «оба полюса = редукция → Φ→0»: гибель наступает не от сжатия как такового, а от потери I. Это «колмогоровский шаблон», не гарантия: K невычислима, обе стороны работают на прокси (компрессия, счёт тем).

**Слой кода (p55 → data7, обратный!).** В коде data7 (knowledge_transformer.rationalize) ограничение НЕ enforced: транзитивные связи и почти-дубли удаляются безусловно, coverage_preserved лишь репортится постфактум, параметра ε нет. Фильтр p55 («удаление отклонено при потере темы») ближе к форме ограничения, чем сам data7 — направление переноса здесь инвертировано.

**Каноническая формулировка гейта редукции (единая для §3.1, §6/p70 и ревизии docs/12):**

> g = 0 при Δlen<0, **кроме** случая I(K′) ≥ (1−ε)·I(K) — тогда g = coh·бонус_сжатия.

Обязательный тест приёмки: исключение не должно воскрешать сценарий б docs/12 §7 («такса→собака» — коллапс-обобщение): если гипероним наследует теги, I почти сохраняется, и без теста коллапс начнёт получать g>0. Критерий: на пяти сценариях а–д ранжирование классов не меняется; коллапс-обобщение по-прежнему даёт φ_t→0. Пока тест не пройден, исключение не включается — несущая стена доказательства §5(A) docs/12 остаётся нетронутой.

### 3.4 У infom: эмбеддинги, снимки графа, retrieval, судья

- **Эмбеддинг-косинус вместо тег-косинуса — эталонный перенос всего плана** (p69): дыра задокументирована владельцем (docs/12 §10 в.2: coh — «доля общих односимвольных тег-букв», квантована {0, 0.5, 0.707, 1}, фальшивая связность «шум дробит пустоту» coh=1); результат проверяем A/B-тестом Φ_tag vs Φ_embed. **Источник — llm_adapter.embed()** (Cohere embed-multilingual-v3.0, Jina embeddings-v3 — оба 1024D, покрывают русский; OpenAI text-embedding-3-small), **не semantic_sim.py**: тот проверен чтением кода и выбыл (32D ручные векторы по ~80 англоязычным техтерминам, LCG-фолбэк — для русского лексикона p32 почти каждый токен уйдёт в детерминированный шум; та же категория игрушки, что заменяемое тег-перекрытие). Путь интеграции: для фиксированного лексикона ~40 слов — дистилляция эмбеддингов в статичный JSON на этапе сборки (сохраняет file://-автономность, снимает латентность), сервис /sim — только для открытого словаря. Статус — «кандидат на закрытие» вопроса №2, не «закрывает»: обязательна перекалибровка (§6, p69).
- **graph_snapshots → Φ\*(t):** временной ряд здоровья реального графа — данные, которых у MERIDIAN нет (см. §4.1 о двух фазах).
- **graphrag_query для p45:** retrieval заменяет только поле cluster захардкоженного словаря P; поля formula/theorem/code/verif требуют отдельного источника (связка с p49 concept-passport) — иначе p45 осознанно деградирует до граф-браузера. «Перепроверить» честно переименовать в «показать опоры»: retrieval — свидетельство, не доказательство.
- **Судья p34 → живой:** первый шаг — направить Base URL на любой OpenAI-совместимый endpoint (LM Studio/OpenAI); infom для этого не нужен. infom оправдан только как **retrieval-augmented judge** (подмешивает контекст из graphrag_query); тогда в стоимость входит façade /v1/chat/completions + CORS. MCP-судья (infom_mcp.py) — отдельный контур «цикл ведёт сессия Claude Code», не апгрейд file://-прототипов.

### 3.5 У in4n: феромоны, сцена, зум

**Статус пары исправлен: код (MERIDIAN) ↔ план (in4n).** p62-pheromone-aquarium.html уже создан (физика Кулон+Гук+демпфирование, Путешественник, феромон, слайдер испарения ρ∈[0.01,0.2]), p63-traveler-duel.html — три стратегии странников на феромонном поле. У in4n феромоны остаются планом; идея заимствована, реализация опередила донора.

- **Роль осей — точно:** испарение ρ — НЕ реализация оси N (это пассивное забывание, новая ось «устаревание», которой в Φ нет); новизна — только мультипликативный бонус при отложении.
- **Анти-ACO правка (обязательная — инверсия целевой функции).** Классический ACO сходится к одному лучшему пути — это буквально случай «застой/повтор» docs/12 §5(C): repP→1 ⇒ N→0 ⇒ φ_t→0. Буквальный перенос максимизировал бы анти-Φ. Три ограничения: (1) ρ строго >0; (2) Δτ = φ_t·cov_t (бонус новых тем — в отложении); (3) кэп τ_max. Цель аквариума — не кратчайший путь, а **площадь устойчивого свечения**. Статус в p62: реализовано **1.5 из 3** — ρ>0 полностью; тематический бонус есть, но в выборе пути (вес ребра 1+2·феромон+0.5·(общая тема)), а не в отложении Δτ; кэп отсутствует.
- **Типизация рёбер:** радиальные (пересекают lv-страты) = аналог оператора ↔ info1; тангенциальные (внутри страты) = аналог coh. Готовый родственник у info1 — VT (§5).
- **Диск Пуанкаре** — кодирует не M(λ), а ДРУГОЙ, асимметричный тезис («полюса мертвы по-разному»: центр-коллапс достижим и терминален, край-шум недостижим и бездонный); полярность совпадает с p38 дословно. Расхождение с симметрией M(λ) фиксируется как осознанное усиление; в p62 — статическая проекция радиуса (полная гиперболика с геодезическими вне бюджета прототипа).
- **Семантический зум** — интерфейсная находка (жест = рычаг); уровни зума привязывать к лестнице docs/14 и α, а не к пространственным кластерам, с сохранением ссылок «из чего собран» (паспорт p49).

## 4. Что каждая система берёт у MERIDIAN

### 4.1 Φ — траекторная витальность (всем)

Ни одна из четырёх не имеет скалярного индикатора «здоровья процесса во времени»: data7 одношагова («фотография»), метрики info1 — независимые коридоры, infom/in4n не имеют теории вовсе.

- **→ infom/in4n — строго в две фазы.** Фаза 1 (инженерная, сейчас): **усечённая Φ\* = avg(g·N·κ)** по диффам graph_snapshots — g = прирост связной компоненты, N = новые узлы/рёбра, κ = фронтир (узлы с неизвлечёнными соседями). Честно называть усечённой: ⟨M⟩ требует λ-разметки узлов, которой нет (§9.1), κ_end на графе знаний не определён (нет «финала шаблона» — это изменение теории, не реализации). Фаза 2 — после λ-эстиматора. Панельная метрика аквариума — Φ̃ (прокси), калибруется против честной Φ (p37/p48); расхождение выше порога = прибор врёт.
- **→ info1:** Φ как единая свёртка поверх коридоров — с оговоркой: Φ мультипликативна и ноль-чувствительна, коридоры независимы; выбор агрегации — проектное решение.
- **→ data7:** гейт Φ (рост×новизна×открытость) на выходе Synthesizer вместо одиночного NS; Φ как вторая метрика результата рядом с cognitive_load (документ должен быть не только лёгким, но и не выродившимся в реферат-«нечто»).

### 4.2 Полюса-гибели — только в честной редакции (data7, info1)

Экспорт возможен только после разделения на два слоя:

- **(а) Аксиома конструкции — НЕ экспортируется как открытие:** Φ→0 на полюсах обеспечено самим dead-гейтом (λ<0.12 ∨ λ>0.88 ⇒ κ→0, p32) — это определение, вшитое в формулу; к тому же полюса в p32 недостижимы (max lv глагола = 3, ⟨B⟩≈const — docs/12 §10 в.1). Ядро само свою теорему численно не воспроизвело. При ревизии docs/12 §5 — сноска: (A) и (B) опираются на спроектированные механизмы; это согласованность конструкции, не эмпирический факт.
- **(б) Фальсифицируемая гипотеза — экспортируется:** «качество реального знания максимально в средней зоне абстрактности, деградирует к полюсам». Для data7 — вместо телеологии «IC/SD суть предохранители от полюсов» проверяемое следствие: *если* пороги — ограждения, их ослабление даёт вырождение, распознаваемое как λ→0/λ→1 (тест §9.2 п.2).

### 4.3 Верифицируемость — лестница docs/14 (data7, info1)

Лестница NUM→FRM→THM→WRD несёт то, чего нет ни у α info1, ни у гипотез data7 — **градиент проверяемости**. Важно: это ТРЕТЬЕ измерение, а не синоним оси абстракции (слово абстрактнее теоремы, но и теорема, и код верифицируемы; контрпример склейки — OWL-онтология: α=+4 при формальной записи; аналог IUPAC-контрпримера docs/14 §2.1).

- **→ data7:** второй фильтр гипотез Synthesizer наряду с NS — гипотеза «число/формула-уровня» проверяема дёшево, «слово-уровня» дорого; сортировка бэклога по стоимости проверки.
- **→ info1:** фасет R∈{NUM,FRM,THM,WRD} каждому α-артефакту + хотя бы integrityCheck из docs/14 §5.3. Без него спецификации info1 — «THM без soundnessCheck»: методология с хорошим DB может 38 циклов сходиться к правдоподобно оформленному бреду, и ни одна из CD/VT/CR/DB этого не поймает (тот же класс дыры, что SemFit — §8 п.8).

### 4.4 Точечные подарки

- **→ in4n:** формула за свечением (яркость = φ_t, критерий приёмки — проходит верификатор p47/p48), раскраска узлов по M(λ), «мёртвые зоны» dead(λ) как визуальный туман; фронт открытости κ как одношаговое dead()-фильтрованное расширение текущей сборки (BFS — только анимация распространения, не вычислитель: b_live контекстно-зависим, BFS контекстно-свободен).
- **→ data7 (код):** enforce гейта p55 «удаление отклонено при потере инварианта» в rationalize() — см. §3.3, слой кода.
- **→ info1 (теория):** M(λ) как объяснение-гипотеза, почему коридор DB<30% работает, — с явным статусом гипотезы, не вывода (связь качественная; численная калибровка — выход p68).

## 5. Метрики здоровья CD/VT/CR/DB на графе фраз — с честной трактовкой формул

Этот раздел исправляет три неверных пересказа формул info1, обнаруженных при сверке с SCIENTIFIC-PAPER.md, и формулирует, что реально переносимо на граф фраз MERIDIAN.

### 5.1 Честные определения (по первоисточнику)

| Метрика | Формула info1 | Честная глосса | Коридор |
|---|---|---|---|
| **DB** | \|Abstract% − Concrete%\|, где проценты — доли документов по знаку α от Total = Abstract+Concrete+Concept | Знаковый индикатор баланса портфеля: \|P(α>0) − P(α<0)\| с разбавлением зоной α=0 | <30% |
| **CD** | (N_links / N_total)·100%, N_links = документы, содержащие содержательные **inline-ссылки** в теле текста | Покрытие содержательными перекрёстными ссылками. Нижний полюс (0 = документы-острова) — патология; **верхний полюс патологией НЕ является** (100% = нет сирот); прежнее прочтение «CD=1 ⇒ всё со всем» — ошибка | 10–20% |
| **VT** | (N_vert / N_total)·100%, N_vert = документы с секциями See also, **типизированными по ⇑⇓↔** | Покрытие типизированной навигацией по вертикали абстракции | 50–70% |
| **CR** | ΔLinks / ΔDocs за цикл | **Convergence Rate: новых связей на новый документ.** Не «поток ⇑/⇓» и не аналог Φ — это **граф-аналог гейта g=(Δlen>0)?coh:0**: новая единица засчитывается, только если пришла связанной | 0.7–1.5 |

**Разрешение парадокса VT≤CD.** По букве определений документ с See-also-секцией содержит ссылки ⇒ VT-документы ⊆ CD-документов ⇒ VT≤CD. Опубликованные данные это нарушают (цикл 38: VT=62.26% > CD=14.97%) — значит, на практике N_links считает только inline-ссылки в теле, исключая навигационные блоки. Метрики **дополнительны, не вложены**: CD — содержательное цитирование, VT — типизированная навигация. Нулевой шаг p68 — зафиксировать определения и воспроизвести 14.97/62.26 на корпусе info1; до этого любой «прогон 38 циклов» через неоднозначные формулы бессмыслен.

### 5.2 Два контрпримера против DB как меры |λ−0.5|

1. **Слепота к амплитуде:** 60% массы на α=+4 и 40% на α=−1 дают DB=20 («здорово») при центре масс далеко от середины. DB — статистика знака, не величины; «штанга» (масса на обоих полюсах) даёт DB≈0 при минимуме ⟨M⟩.
2. **Разбавление нулём:** знаменатель включает Concept (α=0). A=0.6/C=0.4 → DB=20; добавили концепций → A=0.3/C=0.2/Concept=0.5 → DB=10. DB поощряет «всё — концепции», что по теории самого MERIDIAN — застой (сценарий д, N→0).

**Следствие для переноса:** на панель MERIDIAN идёт не DB, а напрямую пара **(λ̄, Var(λ_t))** — обе считаются из уже существующего metrics().lam (p32), не страдают ни слепотой к амплитуде, ни разбавлением. DB_T = |%шагов λ_t>0.5 − %шагов λ_t<0.5| — только как грубый знаковый индикатор с явной пометкой. DB-балансир p71 обязан защищаться от разбавления (баланс потоков ≠ куча на нуле).

### 5.3 Что переносится на граф фраз

- **CR ↔ g — новая прочная пара** (уровень РОЛЬ, сильная): обе метрики вознаграждают только связный рост. Коридор 0.7–1.5 числом не переносить (другая единица и таймскейл: артефакты/цикл-методологии vs ходы/итерацию роя); стартовать с эмпирического бейзлайна по логам p51–p54.
- **VT ↔ типизация рёбер p62** (радиальные=↔ / тангенциальные=coh) — готовый аналог «доли типизированных рёбер»; предусловия: сохранение тегов на ярусе абзацев p54 (сейчас строки — нужна переделка структуры) и honest-семантика после p69.
- **CD** — переносится идея «покрытие связями» как метрика санитарии (нет фраз-островов); идея «коридора с двумя патологическими полюсами» для связности у MERIDIAN сохраняется, но обосновывается собственной теорией (фальшивая coh=1 — docs/12 §10 в.2), а не формулой CD, которая её не содержит.
- **Данные:** опубликованы 4 снапшота (циклы 10/20/30/38): DB 45.0→29.8, CD 8.3→14.97, VT 22.2→62.26, CR 0.42→1.01. Точная формулировка: «траектория снимков 10→38», не «за 38 циклов». Поциклового ряда нет — статус материала см. §8 п.3; единственный шанс на настоящий датасет — git-история репозитория info1 (проверка входит в p68).

## 7. Единый глоссарий: три оси, пять уровней точности

**Маркировка обязательна:** ТОЖДЕСТВО (одна задача, переносим код) / РОЛЬ (одна функция, разные носители — переносим форму, не числа) / МЕТАФОРА (общий образ — переносить нечего) / ПЛАН (хотя бы одна сторона не существует как код) / ПО ПОСТРОЕНИЮ (совпадение обеспечено подгонкой, доказательный вес нулевой). **Правило: пары уровня РОЛЬ и ниже не считаются аргументами в пользу гипотезы «один рычаг».**

## 8. Где аналогии хромают (честно)

Фиксируются в документе, не чинятся:

1. **Один автор пяти систем** — конвергенция терминов и решений не независима; вес переносится на фальсифицируемые следствия (§9.2).
2. **Теорема о полюсах циркулярна в текущем виде:** Φ→0 на полюсах — аксиома dead-гейта, не вывод; полюса в p32 недостижимы (⟨B⟩≈const, docs/12 §10 в.1). Ядро продаёт теорему, которую само не воспроизвело; экспортируется только фальсифицируемая часть (§4.2б).
3. **Материал 38 циклов = Гудхарт + самоотчёт + 16 чисел:** DB снижали как собственный KPI; опубликованы 4 снапшота × 4 метрики, поциклового ряда нет; траектория согласуется с любой унимодальной функцией — форма 4λ(1−λ) по ней не идентифицируема. Статус: калибровочный материал, собранный вне p32, — не подтверждение.
4. **DB ≠ мера |λ−0.5|:** знаковая статистика, слепая к амплитуде и разбавляемая зоной α=0 (два контрпримера §5.2).
5. **data7 — не «промышленность»:** semantic_distance = Jaccard по ключевым словам («упрощенная версия» — по собственной пометке), novelty концептов = константа 0.5, дубли = биграммы; тот же прототипный класс, что p51–p56. TSP-код полезен, но сам по себе не подтверждает production readiness. Числа 40–53% — self-reported без приложенного независимого протокола.
6. **Rationalizer:** формула — вывеска (K невычислима, всё прокси), код не enforce'ит ограничение, а живое обобщение теряет I по определению — критерий сжатия-без-потерь, не критерий здоровой абстракции; ε должна быть большой и уровнезависимой, дополняться проверкой восстановимости (§3.3).
7. **ACO инвертирует целевую функцию** без анти-правок §3.5: сходимость к одному пути = случай «застой» docs/12 §5(C).
8. **«Грамматичный бред» не закрывает никто.** Эмбеддинги дадут близость, но не несочетаемость («бесцветные зелёные идеи яростно спят»; антонимы в эмбеддингах близки). SemFit (docs/12 §10 в.4) открыт для всей пятёрки — единственная общая дыра.
9. **p41 ≠ Кулон+Гук** (проверено кодом: p41 — слияние/деление слов). Силовая раскладка in4n — эстетика читаемости; равновесная дистанция семантически не гарантирована. Карта «отталкивание=дробление, пружины=обобщение» — эвристика-метафора, не вывод.
10. **Диск Пуанкаре не «доказывает M(λ)»** — он кодирует другой, асимметричный тезис (§3.5); «площадь диска = комбинаторика разбиений» — образ, не изоморфизм (разбиения растут по длине слова, площадь — по радиусу; параметры не связаны).
11. **Числовые пороги не переносятся ни в одну сторону:** коридоры info1 откалиброваны на её документном корпусе, а не на траекториях 4–10 шагов; пороги data7 — на диссертациях, не на фразах; пороги MERIDIAN — на тег-модели, не на непрерывном косинусе. Переносится форма, каждое число переоткалибровывается — иначе тираж «константы-иллюстрации» (ДЫРА A docs/14).
12. **Путешественник ≈ поезд p38 — совпадение образа,** не механизма (BFS-волна без выбора vs маршрут с метриками); при переносе алгоритм заменяется целиком; p63-traveler-duel — первая реальная замена.
13. **Лестница docs/14 и ось α — разные измерения** (верифицируемость ≠ абстрактность); их отождествление — самая соблазнительная ошибка формализации; мост только через тип обоснования R.
14. **Самоописания репозиториев-доноров не принимаются на веру** — только чтение кода. Прецедент: semantic_sim.py, заявленный как «настоящая семантическая близость», при проверке оказался 32-мерными ручными векторами по ~80 англоязычным терминам с LCG-фолбэком («детерминированный, но без семантики» — по собственному комментарию кода); центральный тезис угла infom пришлось переписать на llm_adapter.embed. Симметрично: llm_adapter — клиентская библиотека (complete()/embed()), не сервер — «направить Base URL p34 на infom» без FastAPI-фасада невозможно (§3.4).

## 9. Открытые вопросы

### 9.1 Блокеры (без них переносы декларативны)

1. **λ-эстиматора для произвольного текста не существует.** λ=avg(lv)/5 вычислима только внутри лексикона ~40 слов с ручными уровнями. Заблокированы: λ-гейт data7, полная Φ на графе infom, λ-атрибут узлов, следствия №1–2 в полной форме (§9.2).
2. **Субстрата рёбер в движке MERIDIAN нет** — «равноправный ↔» невыразим до шага 1 плана §3.1.
3. **Поцикловых данных info1 нет** (подтверждено: 4 снапшота в SCIENTIFIC-PAPER.md). Единственный путь к настоящему датасету — git-история репозитория info1 (проверка в p68) либо сбор собственного корпуса.
4. **Определения CD/VT/CR требуют фиксации** до любого моста (§5.1, нулевой шаг p68): по букве формул VT≤CD, данные это нарушают — воспроизводимость снапшота 14.97/62.26 обязательна.

### 9.2 Фальсифицируемые следствия (что могло бы опровергнуть «один рычаг»)
