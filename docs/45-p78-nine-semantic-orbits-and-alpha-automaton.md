## 1. Короткое решение

Предложение о девяти орбитах корректно после одного принципиального уточнения:

1. Центр, девять орбит и внешняя граница не образуют одиннадцать уровней абстракции.
2. Все девять полезных уровней `α` находятся **внутри 2D-системы**.
3. Запретный 3D-коллапс расположен глубже орбиты `α=+4`, но сам не является уровнем `α`.
4. Запретный 1D-распад расположен дальше орбиты `α=-4`, но сам не является уровнем `α`.
5. Обобщение идёт радиально внутрь: `α -> α+1`.
6. Детализация идёт радиально наружу: `α -> α-1`.
7. Осмысленное продолжение на том же уровне идёт по касательной: `α -> α` с созданием нового типизированного отношения или артефакта.

Получается не девять декоративных планет, а девять рабочих полос семантического конвейера. Частица на орбите означает артефакт определённого типа. Переход между орбитами означает проверяемую операцию над содержанием. Вращение на месте означает работу на прежнем уровне, только если появился новый проверяемый результат; одна анимация прогрессом не считается.

### 2.2. Почему агенты не вынесли это в итог

Причины воспроизводимы и должны учитываться в следующих аудитах:

1. Задание агентам было сосредоточено на линии P1-P80, исполняемом P78, Рамсее и кластерном конвейере. Конкретный документ `МЕТОДОЛОГИЯ-ПАРАЛЛЕЛЬНОГО-РАЗВИТИЯ.md` не был задан обязательным источником.

3. Нужная конструкция распределена минимум по трём документам, а не сформулирована в одном месте.
4. Слово «уровень» перегружено: им назывались классы инфонов, представления формулы, этапы игры, уровни абстракции и пространственные измерения.

6. Агенты не должны были молча отождествлять эти оси. Ошибка состояла не в осторожности, а в том, что нерешённый конфликт не был вынесен как отдельная задача.

## 3. Четыре оси, которые нельзя смешивать

| Ось | Допустимые значения | Что означает | Где используется |
|---|---|---|---|
| **Пространственный режим** | запретный 3D-центр / безопасное 2D-кольцо / запретный 1D-вылет | риск коллапса или распада системы | гомеостаз, физика интерфейса |
| **Абстракция `α`** | целые `-4..+4` | тип рабочего артефакта и направление преобразования | девять семантических орбит |
| **Гранулярность инфона** | исторические `C0..C5` либо новая размерная шкала кластера | насколько крупен фрагмент содержимого | merge/split, ёмкость очереди |
| **Форма обоснования** | `NUM / FORMULA / THEOREM / WORD` и source-backed статусы | каким способом утверждение проверяется | доказательность и UI инспектора |

Дополнительно существует ось рабочего состояния: `QUEUED / RUNNING / REVIEW / COMMITTED / ROLLED_BACK / ABSTAINED`. Она не определяет ни радиус, ни истинность.

Один артефакт поэтому описывается не одним числом, а кортежем:

```text
ArtifactPosition = (alpha, granularity, representation, workflowState)
```

Например, один короткий фрагмент кода может иметь:

```text
alpha = -4                 // тип артефакта: код
granularity = SMALL_BLOCK  // малый объём
representation = FORMULA  // внутри кода реализована формула
workflowState = REVIEW     // ещё не принят
```

Нельзя выводить `workflowState=COMMITTED` из того, что частица визуально достигла нужной орбиты.

## 4. Топология девяти орбит

### 4.1. Порядок от центра наружу

```text
3D COLLAPSE CORE          запрет: все различия уничтожены
INNER GUARD               откат, PARK или ABSTAIN
alpha=+4  ONTOLOGY        самая внутренняя полезная 2D-орбита
alpha=+3  PHILOSOPHY
alpha=+2  LAWS
alpha=+1  PRINCIPLES
alpha= 0  CONCEPT         серая опорная орбита
alpha=-1  SPECIFICATIONS
alpha=-2  TEMPLATES
alpha=-3  EXAMPLES
alpha=-4  CODE            самая внешняя полезная 2D-орбита
OUTER GUARD               откат, PARK или ABSTAIN
1D DISINTEGRATION FIELD   запрет: связи уничтожены, остаются несвязанные знаки
```

Так выполняются оба требования:

- онтология и код остаются полезными артефактами;
- полное обобщение и полный распад остаются недостижимыми границами.

`α=+4` не означает, что всё сведено к одному слову. Онтология обязана сохранять различимые типы и отношения. `α=-4` не означает бессвязный двоичный шум. Код обязан сохранять интерфейс, тестируемое поведение и связь со спецификацией.

### 4.2. Цвет и дополнительное кодирование

Цветовая схема развивает предложенную последовательность «бело-синий центр → серый ноль → красно-чёрный край»:

| α | Тип | Основной цвет | Дополнительный признак |
|---:|---|---|---|
| +4 | Ontology | `#F4F7FA` белый | двойная тонкая линия |
| +3 | Philosophy | `#B8DDF0` светло-синий | одна длинная риска |
| +2 | Laws | `#4EA8DE` синий | две риски |
| +1 | Principles | `#2A9D8F` зелёно-бирюзовый | три риски |
| 0 | Concept | `#7A7F87` нейтральный серый | сплошная опорная линия |
| -1 | Specifications | `#E9C46A` жёлтый | один короткий штрих |
| -2 | Templates | `#F4A261` оранжевый | два коротких штриха |
| -3 | Examples | `#E76F51` красный | три коротких штриха |
| -4 | Code | `#1B1D22` почти чёрный, обводка `#FF4D4D` | пунктирная граница |

Цвет не должен быть единственным носителем информации. На каждой орбите остаются метка `α`, название типа, форма линии и доступный текстовый статус. Это необходимо для слабовидящих пользователей, монохромного режима и машинных снимков тестов.

### 4.3. Радиус

Пусть `r_inner` и `r_outer` задают границы безопасной рабочей области, причём:

```text
0 < r_core < r_inner < r_outer < r_wall
```

Для `α in {-4,-3,...,+4}`:

```text
k(alpha) = 4 - alpha
r(alpha) = r_inner + (k(alpha) / 8) * (r_outer - r_inner)
```

Следовательно:

```text
r(+4) = r_inner
r( 0) = (r_inner + r_outer) / 2
r(-4) = r_outer
```

Линейная формула рекомендуется для первого интерфейса: расстояния легко читать и тестировать. Геометрическое сгущение из [геометрии MERIDIAN](03-geometry-topology.md) можно включить как визуальный режим, но оно не должно менять семантический порядок.

Обратное преобразование используется только для выбора ближайшей полосы в UI:

```text
alphaView(r) = clamp(round(4 - 8 * (r - r_inner) / (r_outer - r_inner)), -4, +4)
```

Оно не классифицирует текст. Семантический `alpha` задаётся типом артефакта, а не пиксельной координатой.

## 5. Семантическая единица

### 5.1. Артефакт

```ts
type Alpha = -4 | -3 | -2 | -1 | 0 | 1 | 2 | 3 | 4;

type ArtifactKind =
  | 'CODE'
  | 'EXAMPLE'
  | 'TEMPLATE'
  | 'SPECIFICATION'
  | 'CONCEPT'
  | 'PRINCIPLE'
  | 'LAW'
  | 'PHILOSOPHY'
  | 'ONTOLOGY';

interface SemanticArtifact {
  id: string;
  alpha: Alpha;
  kind: ArtifactKind;
  title: string;
  body: string;
  language: string;
  claimRefs: string[];
  sourceRefs: string[];
  parentRefs: string[];
  childRefs: string[];
  horizontalRefs: string[];
  qualifiers: string[];
  contentHash: string;
  authority: 'DRAFT' | 'SOURCE_BACKED' | 'REVIEWED' | 'ABSTAIN';
}
```

Инвариант типа:

```text
alphaOf(kind) == artifact.alpha
```

Если классификатор не уверен, он возвращает несколько кандидатов и `REQUIRES_REVIEW`, а не ставит частицу на случайную орбиту.

### 5.2. Рёбра

```ts
type RelationKind =
  | 'GENERALIZES'
  | 'SPECIALIZES'
  | 'ASSOCIATES'
  | 'USES'
  | 'INCLUDES'
  | 'DEPENDS_ON'
  | 'SUPPORTS'
  | 'REFUTES'
  | 'QUALIFIES'
  | 'IMPLEMENTS'
  | 'INSTANTIATES';

interface SemanticEdge {
  id: string;
  fromRef: string;
  toRef: string;
  relation: RelationKind;
  sourceRefs: string[];
  status: 'PROPOSED' | 'REVIEWED' | 'REJECTED';
}
```

Радиальные рёбра имеют `GENERALIZES`, `SPECIALIZES`, `IMPLEMENTS` или `INSTANTIATES`. Касательные рёбра используют отношения одного уровня. Не типизированная линия запрещена: она выглядит как связь, но ничего проверяемого не сообщает.

### 5.3. Кластер и происхождение

Орбиты не заменяют модель из документа 44. Входной объект остаётся:

```text
SemanticCluster
  + ProvenanceManifest
  + FlowReceipt
```

`alpha` добавляется в семантический граф `G_sem`; переходы и очереди живут в `G_work`; координаты, цвет и анимация живут в `G_view`.

```text
metric(G_view) must not authorize semantic commit
```

Это означает, что скорость, красивый след, число оборотов и близость к центру не дают артефакту статус `SOURCE_BACKED`.

## 6. α-автомат

### 6.1. Состояние

```ts
interface AlphaAutomatonState {
  focusRef: string;
  alpha: Alpha;
  phase: 'IDLE' | 'PROPOSE' | 'VALIDATE' | 'REVIEW' | 'COMMIT' | 'ROLLBACK';
  pendingOperation: AlphaOperation | null;
  evidenceBudget: number;
  attempt: number;
  lastReceiptRef: string | null;
}

type AlphaOperation =
  | 'GENERALIZE'
  | 'SPECIALIZE'
  | 'LINK'
  | 'ORBIT'
  | 'BRIDGE'
  | 'PARK'
  | 'ROLLBACK'
  | 'ABSTAIN';
```

### 6.2. Нормальные переходы

| Оператор | Изменение α | Геометрия | Обязательный результат |
|---|---:|---|---|
| `GENERALIZE` | `+1` | одна орбита внутрь | родительский артефакт и `GENERALIZES` |
| `SPECIALIZE` | `-1` | одна орбита наружу | дочерний артефакт и `SPECIALIZES`/`IMPLEMENTS` |
| `LINK` | `0` | хорда или касательная связь | новое типизированное ребро |
| `ORBIT` | `0` | движение по текущему кольцу | новый проверенный артефакт или receipt |
| `PARK` | `0` | остановка в очереди | причина ожидания и срок/условие возврата |
| `ROLLBACK` | по receipt | обратный визуальный ход | восстановленное подтверждённое состояние |
| `ABSTAIN` | `0` | частица уходит в инспектор, не за стенку | явная причина отказа |

`ORBIT` отличается от декоративного вращения: полный оборот без нового ребра, артефакта или квитанции имеет `semanticProgress=0`.

### 6.3. Гейты обобщения

`GENERALIZE(A_1...A_n -> B)` разрешён, когда одновременно выполнено:

1. `B.alpha = max(A_i.alpha) + 1` для обычного шага.
2. Указана матрица покрытия: какая существенная часть каждого входа представлена в `B`.
3. Не потеряны отрицания, модальность, область действия, числовые ограничения и квалификаторы.
4. Источники входных утверждений сохранены.
5. Не заявлена универсальность шире доказанного корпуса.
6. Проверен хотя бы один контрпример-кандидат.
7. Если покрытие неполно, результат помечен `QUALIFIES` или `ABSTAIN`, а не «истина».

Пример недопустимого обобщения:

```text
Вход: «В исследованной выборке алгоритм A быстрее B при n < 100».
Выход: «A всегда быстрее B».
```

Здесь потеряны выборка и ограничение `n < 100`.

### 6.4. Гейты детализации

`SPECIALIZE(P -> C_1...C_n)` разрешён, когда:

1. `C_i.alpha = P.alpha - 1` для обычного шага.
2. Каждый дочерний артефакт явно указывает родителя.
3. Добавленная конкретика либо выводится из родителя, либо имеет собственный источник.
4. Все обязательные ограничения родителя остаются выполненными.
5. Пример не выдаётся за закон, шаблон не выдаётся за спецификацию, код не выдаётся за доказательство.
6. Суммарное покрытие детей измеряется, но не обязано быть полным; пробелы перечисляются.

### 6.5. Гейт связывания

`LINK(A,B)` разрешён, когда:

```text
A.alpha == B.alpha
relationKind != null
relationWitness != null
duplicateEdge == false
```

Связывание является самостоятельным полезным действием. Оно не обязано изменять абстрактность. Именно этот оператор даёт P78 осмысленное движение по кругу, не заставляя систему бесконечно прыгать внутрь и наружу.

### 6.6. Мост через несколько орбит

`BRIDGE` нужен для практической работы, когда, например, от концепции сразу получен код. Такой переход допустим только как сокращённое представление скрытой цепочки:

```text
Concept -> Specification -> Template -> Example -> Code
```

У моста должны быть:

- `fromAlpha` и `toAlpha`;
- перечень пропущенных уровней;
- свидетель для каждого пропуска;
- флаг `intermediateArtifactsMaterialized`;
- review-решение.

Если свидетелей нет, UI показывает разорванную радиальную линию и `TRACEABILITY_GAP`. Мост не заменяет промежуточные уровни, а фиксирует долг по их восстановлению.

## 7. Псевдокод перехода

```js
function applyAlphaOperation(state, operation, proposal, stores) {
  const before = stores.semantic.get(state.focusRef);
  const targetAlpha = expectedAlpha(before.alpha, operation);

  if (!withinAlphaDomain(targetAlpha)) {
    return rollbackReceipt('ALPHA_BOUNDARY_REACHED', before);
  }

  const candidate = buildCandidate(before, proposal, targetAlpha);
  const structural = validateStructure(before, candidate, operation);
  const provenance = validateProvenance(candidate, stores.sources);
  const semantic = validateSemanticContract(before, candidate, operation);
  const authority = validateAuthority(candidate, operation);

  const failures = [structural, provenance, semantic, authority]
    .flatMap((result) => result.failures);

  if (failures.length > 0) {
    return operation.attempt < operation.retryBudget
      ? parkReceipt(before, failures)
      : abstainReceipt(before, failures);
  }

  const committed = stores.semantic.commit(candidate);
  const edge = stores.semantic.commitEdge(edgeFor(before, committed, operation));
  const receipt = stores.work.commitReceipt({
    operation,
    beforeHash: before.contentHash,
    afterHash: committed.contentHash,
    edgeRef: edge.id,
    validatorVersions: currentValidatorVersions(),
    semanticTruth: false
  });

  stores.view.enqueueProjection({
    artifactRef: committed.id,
    alpha: committed.alpha,
    radius: radiusFor(committed.alpha),
    receiptRef: receipt.id
  });

  return receipt;
}
```

Сначала фиксируется семантическая операция, затем UI получает проекцию. Обратный порядок запрещён: отрисованная смена орбиты не должна подменять commit.

## 8. Как автомат строит продолжение

### 8.1. Вход

Пользователь вводит фразу, абзац, набор источников или существующий артефакт. Система не пытается сразу «продолжить текст». Она создаёт `InputEnvelope`:

```text
InputEnvelope {
  rawText,
  normalizedText,
  claimRefs,
  sourceRefs,
  requestedOutcome,
  candidateAlpha[],
  ambiguityFlags[]
}
```

Определение исходной орбиты выполняется по назначению артефакта, а не только по словам. Фраза «система должна сохранять источники» может быть принципом; тот же текст внутри обязательного нормативного раздела может быть спецификацией. Поэтому классификатор возвращает объяснение и уверенность.

### 8.2. Три кандидата следующего хода

Для принятого входа система строит не один магический ответ, а ограниченную решётку:

```text
INNER  = один кандидат GENERALIZE
ALONG  = один или несколько LINK/ORBIT кандидатов
OUTER  = один или несколько SPECIALIZE кандидатов
```

Каждый кандидат получает:

- ожидаемую пользу;
- риск потери квалификаторов;
- пробелы источников;
- стоимость проверки;
- прогноз изменения связности;
- причину выбора или отказа.

Диспетчер выбирает ход, который создаёт продолжение и не ведёт к крайностям. Если радиальный ход опасен, нормальным продолжением является касательная связь на той же орбите.

### 8.3. Пример полной цепочки

| α | Артефакт |
|---:|---|
| +4 | **Ontology:** информационные объекты состоят из различимых утверждений и типизированных отношений |
| +3 | **Philosophy:** смысл сохраняется не только словами, но и связями, ограничениями и происхождением |
| +2 | **Law:** преобразование не получает более высокий статус достоверности, чем его доказательная база |
| +1 | **Principle:** каждый `merge` и `split` сохраняет claim-level provenance и квалификаторы |
| 0 | **Concept:** кольцевой семантический конвейер с обратимыми переходами |
| -1 | **Specification:** каждый переход создаёт `FlowReceipt` с before/after hash и validator versions |
| -2 | **Template:** JSON-шаблон квитанции перехода |
| -3 | **Example:** заполненная квитанция для обобщения двух утверждений |
| -4 | **Code:** функция валидации и тесты квитанции |

Эта таблица не утверждает, что любой проект обязан иметь ровно один файл на каждом уровне. Она показывает трассу «почему?» внутрь и «как?» наружу.

### 8.4. Осмысленное движение по одной орбите

Пусть на `α=0` существуют концепты:

```text
«кольцевой конвейер»
«версионируемый граф утверждений»
«очередь с обратным давлением»
```

Касательное продолжение может создать связи:

```text
кольцевой конвейер USES очередь с обратным давлением
версионируемый граф DEPENDS_ON квитанции переходов
кольцевой конвейер ASSOCIATES_WITH версионируемый граф
```

Система продолжила смысл, не уходя ни в онтологию, ни в код. Это и есть самостоятельная 2D-работа середины.

## 9. Связь с формулами P78

### 9.1. α не заменяет λ

`α` дискретен и описывает тип артефакта. `λ` непрерывен и описывает управляющий баланс обобщения/детализации. Допустима только роль, а не числовое тождество:

```text
GENERALIZE обычно повышает alpha и увеличивает локальное стремление lambda
SPECIALIZE обычно понижает alpha и уменьшает локальное стремление lambda
```

Нельзя без калибровки писать `lambda = (alpha + 4) / 8`: это искусственная линейная шкала, а не измеренный закон. Такая формула допустима только как координата ползунка UI с именем `alphaView`, но не как семантическая метрика.

### 9.2. Гомеостаз

Для маршрутизации можно использовать штраф близости к границам:

```text
boundaryRisk(alpha) = (abs(alpha) / 4)^p, p >= 2
```

Но на `alpha=+4` и `alpha=-4` риск не означает патологию. Он означает, что следующий шаг в том же радиальном направлении требует особого решения:

```text
GENERALIZE from +4 -> blocked by INNER_GUARD
SPECIALIZE from -4 -> blocked by OUTER_GUARD
```

Штраф влияет на диспетчеризацию, но не обесценивает онтологию или код.

### 9.3. Оценка полезного хода

Кандидат может ранжироваться многокритериально:

```text
utility(move) =
    w_cov   * coverageGain
  + w_link  * typedLinkGain
  + w_nov   * boundedNovelty
  + w_trace * traceabilityGain
  - w_loss  * qualifierLossRisk
  - w_src   * provenanceGap
  - w_edge  * boundaryRisk(targetAlpha)
  - w_cost  * reviewCost
```

Все компоненты должны выводиться отдельно. Один итоговый балл не получает права автоматически принять утверждение. При критической потере источника или квалификатора действует жёсткий veto независимо от `utility`.

## 10. Интерфейс P78

### 10.1. Основное поле

1. Девять концентрических полос всегда имеют стабильные радиусы.
2. `α=0` визуально выделена как нейтральная рабочая опора, но не как единственно правильная орбита.
3. Внутренняя и внешняя защитные зоны видимы, но не являются рабочими полосами.
4. Частица показывает тип артефакта формой значка, а статус работы — малым индикатором состояния.
5. Радиальный след показывает `GENERALIZE` или `SPECIALIZE`.
6. Касательная дуга показывает `LINK` или `ORBIT`.
7. Разорванная линия показывает `TRACEABILITY_GAP`.
8. Полный оборот без semantic receipt не увеличивает счётчик содержательного прогресса.

### 10.2. Инспектор выбранного артефакта

Инспектор должен показывать:

- `α` и тип артефакта;
- текстовый результат;
- исходные claims и sources;
- родительские, дочерние и горизонтальные связи;
- последнюю операцию и её receipt;
- потерянные/сохранённые квалификаторы;
- статус доказательности;
- причины `PARK`, `ROLLBACK` или `ABSTAIN`.

Главный результат остаётся текстовым. Графика помогает увидеть траекторию и пробелы, но не заменяет сформулированный вывод.

### 10.3. Управление

Для явной команды достаточно трёх основных действий:

```text
INWARD    GENERALIZE
ALONG     LINK / continue at same alpha
OUTWARD   SPECIALIZE
```

Автоматический режим предлагает действие, но показывает его до commit. В source-backed и научном режимах принятие нового утверждения требует review. `ABSTAIN` остаётся нормальным исходом.

### 10.4. Производительность

Девять окружностей не должны пересчитываться каждый кадр. Рекомендуемое разделение:

```text
staticCanvas: rings, labels, guard zones
dynamicCanvas: particles, trails, selection
DOM inspector: text, receipts, controls
```

Семантические вычисления выполняются по событиям или в worker, а `requestAnimationFrame` только интерполирует уже рассчитанное состояние. Это предотвращает прежние паузы вращения из-за синхронной обработки текста.

## 12. Проверки и фальсификация

### 12.1. Структурные тесты

1. Для всех девяти `α` существует ровно один `ArtifactKind`.
2. `r(+4) < r(+3) < ... < r(-4)`.
3. `r(0)` находится посередине безопасного кольца.
4. Обычный радиальный переход изменяет `α` ровно на единицу.
5. `LINK` не меняет `α`.
6. `GENERALIZE` из `+4` и `SPECIALIZE` из `-4` отклоняются.
7. `BRIDGE` без witness chain отклоняется.
8. Любой commit имеет before/after hash и validator versions.
9. Событие из `G_view` не может вызвать semantic commit.

### 12.2. Семантические golden-тесты

- сохранение отрицания;
- сохранение числовых диапазонов;
- сохранение модальности «может / должен»;
- сохранение области «в выборке / всегда»;
- запрет неподтверждённой конкретики;
- различение примера и закона;
- различение шаблона и спецификации;
- типизация горизонтальных отношений;
- корректный `ABSTAIN` при недостатке источников.

### 12.3. Свойства round-trip

Текстовая идентичность после цикла не требуется:

```text
A --GENERALIZE--> B --SPECIALIZE--> A'
```

Требуются более содержательные свойства:

```text
requiredClaims(A) subsetOf supportedClaims(A')
qualifiers(A) subsetOf qualifiers(A')
sourceCoverage(A') >= requiredThreshold
contradictions(A, A') == empty
```

Если конкретика была сознательно отброшена при обобщении, она должна остаться доступной через ссылки на дочерние артефакты.

### 12.4. Что опровергнет полезность модели

Модель девяти орбит следует отвергнуть или пересмотреть, если:

1. аннотаторы систематически не могут различать соседние уровни;
2. один и тот же тип артефакта устойчиво требует нескольких несмежных `α` без контекста;
3. промежуточные уровни не улучшают трассируемость и только создают бюрократию;
4. касательные связи не дают измеримого прироста восстановления источников или навигации;
5. пользователи принимают цвет и движение за оценку истинности даже после явного разделения интерфейса;
6. автоматический классификатор не превосходит простую базовую эвристику на blind holdout.

## 13. Ограничения и запреты

1. Девять уровней не являются «законом природы» и не доказываются геометрией.
2. Онтология не является 3D-коллапсом; код не является 1D-шумом.
3. `α=0` является опорным типом «Concept», а не универсальной истиной и не обязательным местом каждой частицы.
4. Не требуется создавать бессодержательный документ ради заполнения каждой орбиты.
5. Цвет, радиус, масса, скорость и число оборотов не дают authority.
6. Автомат не может повышать достоверность результата выше достоверности источников.
7. Прямой прыжок через уровни не скрывается: он создаёт `TRACEABILITY_GAP` либо witness chain.
8. Операции над текстом не объявляются физическими законами жидкости; гидродинамика остаётся моделью диспетчеризации и интерфейса.
9. `G_sem`, `G_work` и `G_view` не сливаются в один граф.
10. AG5 остаётся заблокированным до отдельного corpus holdout независимо от готовности девяти орбит.

## 14. Итог

Девять уровней из `info1` действительно дают P78 недостающую дискретную семантическую топологию. Их правильное место — не между «1D снаружи» и «3D в центре» как две крайние рабочие точки, а **внутри самостоятельного безопасного 2D-кольца**. Тогда:

- внутрь идёт контролируемое обобщение;
- наружу идёт контролируемая детализация;
- по окружности идёт равноправное связывание и продолжение;
- защитные зоны не позволяют полезной онтологии стать коллапсом, а полезному коду — бессвязным распадом;
- каждый графический переход имеет тип, текстовый результат, источник и receipt.

Это превращает старую визуальную метафору в проверяемый α-автомат. Следующий технический шаг — срез A: контракты и тесты переходов без изменения основного Canvas P78.
