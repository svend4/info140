# P78 и внедиагональные числа Рамсея: формулы, границы и допустимый перенос

Дата: 2026-07-19  
Статус: исследовательская записка; не является доказательством свойств P78  
Основной источник: [Domagoj Bradač, *Off-diagonal Ramsey numbers*, arXiv:2605.28793v3](https://arxiv.org/abs/2605.28793), [PDF](https://arxiv.org/pdf/2605.28793)

## 1. Краткий вывод

Связь с P78 содержательная, но не буквальная.

- В теории Рамсея рассматриваются две точные крайности графа: полностью связанная группа и полностью несвязанная группа.
- В P78 им можно сопоставить две опасные тенденции: чрезмерное смысловое замыкание/сжатие и распад деталей без мостов.
- Теорема Рамсея не создаёт автоматически «2D-середину». Напротив, она говорит, что в достаточно большом неизменном графе одна из крайних конфигураций неизбежно появится.
- Поэтому бесконечное продолжение P78 возможно только как работа открытой системы: менять активное окно, добавлять и ослаблять связи, архивировать элементы, строить мосты, проверять результат и уметь откатывать ход.
- Самая полезная для P78 деталь новой работы — не итоговая асимптотическая граница, а новая асимметричная конструкция `D*`: движение возникает, когда одна перекрёстная связь есть, а обратной нет.

Главная переносимая идея:

```text
обе перекрёстные связи есть   -> замыкание / 3D-тенденция
обеих перекрёстных связей нет -> распад / 1D-тенденция
ровно одна связь есть         -> направление / 2D-продолжение
```

Это можно превратить в вычислимую модель без заявления, что P78 «решает задачу Рамсея».

## 2. Что именно доказано в работе

Для положительных целых `s` и `k` число Рамсея `r(s,k)` — минимальное `n`, при котором любой граф на `n` вершинах содержит либо клику `K_s`, либо независимое множество размера `k`.

Новая нижняя граница для фиксированного `s >= 3` и растущего `k`:

```math
r(s,k) >= c_s * k^(s-1) / (log k)^(2s-4).
```

Лучшая известная верхняя граница имеет вид:

```math
r(s,k) <= (1 + o(1)) * k^(s-1) / (log k)^(s-2).
```

Следовательно, главный степенной показатель определён:

```math
r(s,k) = k^(s-1+o(1)),
lim[k->infinity] log r(s,k) / log k = s - 1.
```

Разрыв не исчез полностью. Между границами остаётся полилогарифмический множитель порядка `(log k)^(s-2)`, неизвестны точные константы и большинство конкретных значений.

Первая версия работы давала более слабую оценку:

```math
r(s,k) >= c_s * k^(s-2) / (log k)^(2s-6).
```

Переход от `s-2` к `s-1`, найденный внутренней моделью OpenAI и проверенный автором, улучшает первую версию примерно в

```math
k / (log k)^2
```

раз. Это асимптотически большое, а не косметическое усиление.

## 3. Основные формулы конструкции

### 3.1 Полярный граф

Берётся конечное проективное пространство `PG(t,q)`. Его вершины — одномерные подпространства `F_q^(t+1)`. Вершины, представленные векторами `x` и `y`, соединены тогда и только тогда, когда

```math
<x,y> = sum[i=1..t+1] x_i y_i = 0.
```

Получается псевдослучайный `(n,d,lambda_spec)`-граф:

```math
n ~ q^t,
d ~ q^(t-1),
lambda_spec ~ sqrt(d).
```

Здесь `lambda_spec` — модуль нетривиального собственного значения матрицы смежности. Это не тот же параметр, что существующий ползунок `lambda` в P78. В коде их нельзя называть одинаково.

Смысл спектральной оценки: граф достаточно регулярно перемешивает связи. Для множеств вершин `A` и `B` expander mixing lemma ограничивает отклонение числа рёбер от случайноподобного ожидания:

```math
|e(A,B) - d|A||B|/n| <= lambda_spec * sqrt(|A||B|).
```

### 3.2 Старая парная конструкция

В исходной схеме вершинами ориентированного графа были пары `(a,b)`, не образующие ребро базового графа. Переход к следующей паре задавался одной перекрёстной связью. Эта схема давала запрет транзитивного турнира нужного размера при `t=s-2`, а после выборки — показатель `s-2`.

### 3.3 Новая конструкция `D*`

В улучшенной схеме вершина `D*(t,q)` — связанная пара:

```math
V(D*) = {(a,b) | ab in E(G)}.
```

Направленная дуга определяется асимметрией двух перекрёстных отношений:

```math
(a,b) -> (a',b')
iff
ab' in E(G) and a'b not in E(G).
```

Эта конструкция не содержит транзитивного турнира `T_(t+1)`. Экономия одной вершины в запрещённой конфигурации позволяет взять

```math
t = s - 1
```

вместо `t = s - 2`. Именно эта единица превращается в дополнительную степень `k`.

### 3.4 Подсчёт и выборка

Для достаточно больших `q` и

```math
k >= C q (log q)^2
```

число прямых независимых `k`-кортежей в `D*` ограничивается как

```math
i_forward_k(D*) <= (C q^t)^k.
```

Случайная перестановка вершин и сохранение только направленных вперёд рёбер создают обычный граф без `K_s`. Для числа его независимых `k`-множеств получается

```math
i_k(Gamma*) <= (e/k)^k * i_forward_k(D*)
             <= (e C q^t / k)^k.
```

Затем выбирается вероятность сохранения вершины

```math
p = k / (e C q^t),
```

так что `p^k i_k(Gamma*) <= 1`. После случайной выборки и удаления одной вершины из каждого оставшегося плохого независимого множества сохраняется граф без обеих запрещённых структур.

При `q` порядка `k/(log k)^2` и `t=s-1` размер оставшегося графа имеет порядок

```math
k q^(t-1)
~ k^(s-1) / (log k)^(2s-4).
```

## 4. Точное соответствие терминов P78

| Теория графов | Возможный объект P78 | Статус соответствия |
| --- | --- | --- |
| вершина | токен, тег, понятие или фразовый блок одного масштаба | допустимая модель после фиксации масштаба |
| ребро | семантическая связь с `SemFit >= tau` | допустимо, если порог `tau` задан явно |
| вес ребра | `SemFit`, связь через LCA, мост, причинная совместимость | уже частично вычисляется |
| клика `K_s` | группа попарно сильно связанных единиц | точное графовое свойство |
| независимое множество | группа без сильных связей при пороге `tau` | точное графовое свойство |
| `s` | минимальный размер опасного плотного замыкания | параметр модели, не «измерение» |
| `k` | максимально терпимое число взаимно неподдержанных деталей | параметр активного окна |
| `n` | число активных единиц выбранного масштаба | точное количество |
| `d` | средняя сильная степень | вычислимо |
| `lambda_spec` | спектральная нерегулярность/смешивание графа | вычислимо, но ещё не реализовано |
| случайная выборка `p` | ограниченное внимание или выбор активного контекста | инженерная аналогия |
| удаление плохих вершин | архивирование/исключение опасного элемента с квитанцией | инженерная аналогия |
| `D*`-вершина `(a,b)` | типизированная пара «смысл + опора/контекст» | структурный перенос |
| дуга `D*` | одна перекрёстная связь проходит, обратная не проходит | наиболее полезный структурный перенос |

Нельзя отождествлять без оговорки:

- клику и «3D» как математические объекты;
- независимое множество и «1D» как математические объекты;
- кольцо на Canvas и граф размерности 2;
- ползунок `lambda` P78 и спектральное `lambda_spec` статьи;
- существующую эвристику P78 и доказанную нижнюю границу Рамсея.

Клика может содержать богатые разные смыслы, а не только один обобщённый смысл. Независимое множество зависит от выбранного порога связи. Поэтому «3D/2D/1D» остаются семантическими режимами интерфейса, а клики и независимые множества становятся измерителями риска этих режимов.

## 5. Почему две крайности не дают середину автоматически

Теорема Рамсея утверждает неизбежность локальной крайней структуры в достаточно большом статическом графе. Она не утверждает существование устойчивого третьего состояния.

Отсюда следует важное ограничение проекта:

```text
неизменный граф + неограниченный рост -> крайняя подструктура неизбежна
```

Значит, «вечное 2D-движение» нельзя определять как полное отсутствие всех клик и независимых множеств. Реалистичная цель:

```text
крайности могут локально возникать,
но ни одна из них не должна захватывать весь активный контекст;
система должна обнаруживать их, локально преобразовывать и продолжать ход.
```

Для этого P78 нужны уже намеченные механизмы:

1. ограниченное активное окно;
2. иерархия масштабов: буква -> слово -> фраза -> тема;
3. направленные мосты вместо полной взаимной связи;
4. архивирование вместо необратимого удаления;
5. предварительный просмотр изменения;
6. проверка границ до и после;
7. точный откат по снимку.

## 6. Переносимая формула трёх состояний

Пусть имеются две типизированные пары `f=(a,b)` и `g=(a',b')`. Обозначим нормированные силы перекрёстных связей:

```math
x = w(a,b') in [0,1],
y = w(a',b) in [0,1].
```

Жёсткая конструкция `D*` разрешает направленный ход `f -> g`, когда `x=1`, `y=0`.

Для P78 можно использовать непрерывное разложение:

```math
P_3D      = x y,
P_1D      = (1-x)(1-y),
P_2D_fwd  = x(1-y),
P_2D_rev  = (1-x)y,
P_2D      = P_2D_fwd + P_2D_rev.
```

Всегда выполняется:

```math
P_3D + P_1D + P_2D = 1.
```

Интерпретация:

- `P_3D`: обе стороны уже взаимно замкнуты; возникает риск избыточного обобщения или повторения;
- `P_1D`: ни одна сторона не поддерживает другую; возникает риск смыслового распада;
- `P_2D_fwd`: есть направленное продолжение вперёд;
- `P_2D_rev`: возможен обратный ход;
- `P_2D`: асимметрия создаёт движение, не сводя всё к полной связи и не оставляя элементы разобщёнными.

Пример:

```text
x=0.85, y=0.20
P_3D=0.17
P_1D=0.12
P_2D_fwd=0.68
P_2D_rev=0.03
P_2D=0.71
```

Такое состояние естественно трактовать как сильный направленный 2D-ход.

Для набора допустимых переходов значения усредняются с весами уверенности `c_j`:

```math
Center = sum_j c_j P_3D(j) / sum_j c_j,
Edge   = sum_j c_j P_1D(j) / sum_j c_j,
Orbit  = sum_j c_j P_2D(j) / sum_j c_j.
```

Минимальный запас устойчивости:

```math
Margin = Orbit - max(Center, Edge).
```

`Margin > 0` означает, что направленное продолжение сильнее обеих крайних тенденций. Это инженерный критерий P78, не теорема из статьи.

## 7. Графовые метрики, которые можно добавить

### 7.1 Пороговый семантический граф

Из взвешенной матрицы `W` строится наблюдаемый граф:

```math
A_ij(tau) = 1, если W_ij >= tau и связь не помечена как конфликт;
A_ij(tau) = 0 иначе.
```

Порог, масштаб единицы и происхождение веса должны попадать в trace. Без них слова «клика» и «независимое множество» непроверяемы.

### 7.2 Давление замыкания

Для минимальной клики из трёх элементов можно считать число треугольников `T` и глобальную долю:

```math
Closure_3 = T / choose(n,3).
```

Дополнительно нужна локальная максимальная плотность, иначе маленькая плотная группа потеряется в большом графе.

### 7.3 Давление распада

Для небольшого активного окна можно точно или ограниченно искать максимальное независимое множество `alpha_tau`:

```math
Fragment = alpha_tau / n.
```

Для больших окон следует использовать детерминированную оценку и показывать `LOWER_BOUND`/`UPPER_BOUND`, а не выдавать приближение за точное значение.

### 7.4 Спектральное смешивание

Для симметричной нормированной матрицы

```math
B = D^(-1/2) W D^(-1/2)
```

можно оценить максимальный модуль нетривиального собственного значения `rho_mix`. Рабочая оценка смешивания:

```math
Mix = 1 - clamp(rho_mix, 0, 1).
```

Высокий `Mix` означает, что связи распределены без крупных изолированных областей и без одного полностью доминирующего узла. Это аналог идеи псевдослучайности, но не проверка условий полярного графа статьи.

### 7.5 Итоговый критерий продолжения

Практический рейтинг кандидата:

```math
ContinueScore = Orbit
              * SemFit
              * Novelty
              * GuardAfter
              * (1 - ConflictRisk).
```

Кандидат принимается только если одновременно:

```text
ContinueScore >= theta_continue
GuardAfter >= theta_guard
Center <= center_limit
Edge <= edge_limit
точная транзакция имеет статус READY
```

### 7.6 Проверка пригодности текущего графа P78

Текущий граф интерфейса пока нельзя напрямую использовать для рамсеевских метрик. В нём число связей ограничивается для скорости, а при недостатке семантических рёбер добавляются резервные и последовательные связи. Поэтому клика или независимое множество в этой проекции отражают одновременно смысл текста и правила визуализации.

Контрольный аудит трёх уже используемых сценариев дал:

| сценарий | число вершин `n` | максимальная клика `omega` | максимальное независимое множество `alpha` |
| --- | ---: | ---: | ---: |
| сжатие к центру | 11 | 4 | 8 |
| распад к краю | 14 | 6 | 9 |
| безопасное движение | 12 | 5 | 8 |

Эти числа не разделяют две крайности в ожидаемом направлении: сценарий распада имеет и наибольшую клику. Значит, простая замена текущих `core/edge` на `omega/alpha` была бы регрессией.

Для отдельного порогового графа можно показывать диагностический запас до заданных локальных крайностей:

```math
Delta_R = min(s - omega_tau, k - alpha_tau).
```

- `Delta_R > 0`: ни один заданный локальный предел ещё не достигнут;
- `Delta_R = 0`: достигнута хотя бы одна граница;
- `Delta_R < 0`: граница превышена.

Это расстояние до выбранных инженерных ограничений, а не вычисление числа Рамсея. На первом этапе `omega_tau`, `alpha_tau` и `Delta_R` должны быть только диагностикой расширенного режима и не участвовать в `Phi`, guard или автоматическом решении.
## 8. Что нельзя брать из итоговой границы как рабочий порог

Формулы `r(s,k)` асимптотические, содержат неизвестную константу `c_s` и член `o(1)`. Они описывают худший случай среди всех графов, а не реакцию конкретного небольшого текста.

Особенно важно: если в P78 зафиксировать минимальную плотную крайность `s=3`, новая общая граница Брадача не является лучшей численной границей для этого специального случая. Поэтому нельзя вычислять по ней красную зону интерфейса.

Допустимое использование границ:

- исследовательская справка о неизбежности крайностей при росте;
- интервал неопределённости, явно помеченный как теоретический;
- аргумент в пользу активного окна, локального ремонта и архива.

Недопустимое использование:

- объявлять конкретный текст «выше числа Рамсея»;
- подставлять количество слов вместо `n` без определения рёбер и масштаба;
- считать асимптотическую нижнюю границу точным порогом;
- называть эвристику P78 доказательством устойчивости.

## 9. Предлагаемый этап реализации

После завершения Primary Action Flow добавить изолированный модуль, например:

```text
prototype/lib/semantic-asymmetric-balance.js
prototype/tests/semantic-asymmetric-balance-regression.cjs
```

Чистый API:

```text
crossState(x, y)
buildFlags(graph, options)
rankTransitions(flags, options)
aggregate(transitions)
```

Обязательные инварианты:

1. все компоненты находятся в `[0,1]`;
2. `P_3D + P_1D + P_2D = 1` с заданной погрешностью;
3. `(1,1)` даёт чистую 3D-тенденцию;
4. `(0,0)` даёт чистую 1D-тенденцию;
5. `(1,0)` и `(0,1)` дают чистое направленное 2D-движение;
6. перестановка `x,y` меняет направление, но не общий `P_2D`;
7. одинаковый ввод всегда даёт одинаковый результат;
8. ни один результат не изменяет текст без транзакции и предварительного просмотра.

В расширенном режиме интерфейса показывать четыре величины:

```text
замыкание 3D
движение 2D ->
движение 2D <-
распад 1D
```

Рядом обязательно указывать происхождение:

```text
структурная модель P78, вдохновлённая асимметрией D*;
не является вычислением числа Рамсея.
```

## 10. Решение для текущего проекта

Внедрять сейчас саму асимптотическую формулу `r(s,k)` в реакцию не следует. Внедрять стоит асимметричный локальный оператор из раздела 6 и измерители из раздела 7.

Порядок:

1. закончить единый путь `ввод -> прогноз -> guard -> применить -> откат`;
2. добавить чистый модуль асимметричного баланса и граничные тесты;
3. подключить его к существующему `SemFit` как дополнительное, а не заменяющее доказательство;
4. показать метрики только в расширенном анализе;
5. провести набор текстовых сценариев: замыкание, распад, прямой ход, обратный ход, неоднозначность;
6. лишь после наблюдений решать, нужен ли спектральный показатель `rho_mix`.

Так теория Рамсея даёт P78 не декоративную ссылку, а строгую инженерную дисциплину: определить крайности, измерять их на одном масштабе, не обещать невозможного для растущего статического графа и поддерживать продолжение через контролируемую асимметрию.
## 11. Статус реализации

Изолированный вычислительный слой реализован:

```text
prototype/lib/semantic-asymmetric-balance.js
prototype/tests/semantic-asymmetric-balance-regression.cjs
```

API `1.0.0`:

```text
crossState(x, y)
buildFlags(pairs, {weight})
rankTransitions(items, options)
aggregate(items)
```

Проверены `11/11` контрактов:

- точные углы `(1,1)`, `(0,0)`, `(1,0)`;
- разложение `P_3D + P_1D + P_2D = 1`;
- смена направления при перестановке `x,y`;
- отказ на нечисловых и выходящих за диапазон весах;
- явное вычисление перекрёстных отношений двух типизированных пар;
- детерминированная формула `ContinueScore`;
- пороги `ELIGIBLE/BLOCKED`, задаваемые только вызывающей стороной;
- взвешенное объединение без изменения исходных данных;
- отсутствие DOM, сети, транзакций и записи текста.

Модуль намеренно не загружается страницей и не участвует в guard/решении. Условие следующего этапа остаётся прежним: отдельный граф с явными `tau`, масштабом единицы и происхождением каждого веса. До этого формула является проверенным вычислительным кирпичом, а не рабочей семантической мерой.
