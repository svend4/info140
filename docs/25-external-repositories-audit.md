# P78: аудит `svend4/meta` и `svend4/pro2`

Дата: 2026-07-19  
Режим: чтение и концептуальное сопоставление; исходный код внешних репозиториев не переносился

Проверенные снимки:

- [`svend4/meta@21065a9`](https://github.com/svend4/meta/commit/21065a96ba0df1e2e1060c8ede8e4e2d5050ffda)
- [`svend4/pro2@0f89715`](https://github.com/svend4/pro2/commit/0f897158e1a5f5dda9cedee158733324cf8258e4)

## 1. Итог

Оба репозитория полезны как каталоги экспериментальных конструкций, но не как готовые зависимости P78.

| репозиторий | что в нём реально есть | решение для P78 |
| --- | --- | --- |
| `meta` | Python-монорепозиторий вокруг графа `Q6=(Z2)^6`, конечных автоматов, симметрий, MDS и большого архива документов | брать независимо воспроизведённые алгоритмические идеи, не переносить Solan-«семантику» и весь runtime |
| `pro2` | исследовательский PyTorch-монорепозиторий: Q6-кодбук, квантизаторы, MoE-маршрутизация, межмодульные мосты и Nautilus-адаптеры | брать форму диагностики источников и офлайн-эксперименты, не подключать модели и checkpoints к рабочему контуру |

Главное ограничение: в обоих снимках отсутствует файл `LICENSE`. В `pro2` README сообщает `MIT License`, но полного лицензионного текста и copyright notice нет. До исправления лицензионного следа нельзя дословно копировать код; ниже предлагается clean-room реализация общеизвестных алгоритмов и собственных контрактов P78.

## 2. Что полезно из `meta`

### 2.1 Один изменяемый признак за эксперимент

В [`hexcore.py`](https://github.com/svend4/meta/blob/21065a96ba0df1e2e1060c8ede8e4e2d5050ffda/libs/hexcore/hexcore.py#L36-L116) функции `neighbors`, `hamming` и `gray_code` задают простую дисциплину:

```text
соседнее состояние отличается ровно одним битом;
маршрут Gray code посещает 64 состояния без одновременной смены нескольких битов.
```

Для P78 это полезно не как кодирование смысла гексаграммой, а как стенд причинности. Можно бинаризовать шесть измеряемых условий:

```text
coverage_ok
guard_ok
orbit_dominant
novelty_ok
evidence_agrees
conflict_absent
```

Тогда сравнение соседних ячеек показывает реакцию на одно изменение. Это делает результат объяснимее, чем произвольная одновременная перестройка всех параметров.

### 2.2 Проверка жизненного цикла действия

[`hexspec/verifier.py`](https://github.com/svend4/meta/blob/21065a96ba0df1e2e1060c8ede8e4e2d5050ffda/projects/hexspec/verifier.py#L49-L160) проверяет достижимые состояния, тупики, запрещённые состояния, путь и инварианты конечного автомата.

В P78 следует независимо реализовать малый проверяющий автомат:

```text
EVALUATED -> READY | GATED | BLOCKED
READY -> COMMITTED
COMMITTED -> ROLLED_BACK
ROLLED_BACK -> REPLAYED
manual edit -> STALE
```

Нужные свойства:

1. `COMMITTED` недостижим без `READY`;
2. `ROLLED_BACK` недостижим без квитанции точного commit;
3. `REPLAYED` разрешён только из `ROLLED_BACK` и при совпадении source/target;
4. `STALE` не может менять пользовательский текст;
5. нет неконечных циклов, которые мутируют текст без нового решения.

Это хорошо дополняет уже созданный `p78-semantic-action-controller` и полезнее прямого переноса Q6-runtime.

### 2.3 Честность двумерной карты

[`mds_stress`](https://github.com/svend4/meta/blob/21065a96ba0df1e2e1060c8ede8e4e2d5050ffda/projects/hexglyph/solan_mds.py#L146-L166) использует Kruskal stress-1:

```math
Stress = sqrt(sum_(i<j) (d_sem(i,j)-d_2D(i,j))^2 / sum_(i<j) d_sem(i,j)^2).
```

Это можно применить к архипелагу P78 как диагностический показатель искажения: насколько расстояния нарисованной 2D-карты сохраняют исходные расстояния `1-SemFit`. Самодельный eigensolver переносить не надо; расчёт координат должен использовать проверенную библиотеку или уже имеющуюся раскладку, а `Stress` только оценивает результат.

### 2.4 Реестр модулей и dry-run

Форма реестра и pipeline в `meta` полезна как напоминание, что каждому модулю P78 нужны:

```text
id, version, input schema, output schema,
evidence level, owner, timeout, dependencies,
READY/PARTIAL/ABSTAIN/BLOCKED.
```

Сам `q6ctl` подключать не следует: P78 уже имеет более строгие runtime-state, transaction, rollback и ledger.

## 3. Что полезно из `pro2`

### 3.1 Q6 только как вторичный диагностический индекс

[`generate_hexagrams()`](https://github.com/svend4/pro2/blob/0f897158e1a5f5dda9cedee158733324cf8258e4/yijing_transformer/models/geometry/core.py#L20-L44) буквально создаёт декартово произведение `{-1,+1}^6`. Это корректный гиперкуб из 64 вершин, но само по себе не доказывает семантической онтологии.

Допустимое применение в P78:

- ячейка покрытия шести измеряемых флагов;
- поиск соседнего контрфактического сценария по расстоянию Хэмминга;
- обнаружение непроверенных областей и коллизий;
- визуализация траектории экспериментов.

Недопустимое применение: объявить вершину Q6 значением слова или заменить `SemFit` номером гексаграммы.

### 3.2 Версионированный протокол источника

[`PortalEntry` и `BaseAdapter`](https://github.com/svend4/pro2/blob/0f897158e1a5f5dda9cedee158733324cf8258e4/nautilus/adapters/base.py#L10-L55) задают полезную минимальную форму адаптера. Для P78 её надо усилить:

```text
providerId
providerVersion
queryHash
contentHash
format
provenanceLinks[]
coverage
confidence
status = READY | PARTIAL | ABSTAIN | INVALID | UNAVAILABLE
evidenceLevel
soundness
```

Источник не должен бросать рабочий поток, а его отсутствие должно давать `ABSTAIN/UNAVAILABLE`, не выдуманный результат.

### 3.3 Наблюдаемая маршрутизация evidence

Из маршрутизаторов `pro2` полезна не нейросетевая реализация, а требование показывать:

```text
какой источник повлиял на ветвь;
его покрытие и вес;
почему он был принят или отклонён;
какие источники дублируют друг друга.
```

Первый безопасный вариант - read-only таблица вкладов. Вес внешнего evidence остаётся ограниченным и не может обходить guard, action-controller, transaction и ledger.

### 3.4 Попарная медиация вместо плоского среднего

Конструкция `BridgeOfModules` подсказывает проверяемый детерминированный эксперимент:

```text
structural evidence + corpus evidence -> pair A
reaction evidence + graph evidence    -> pair B
pair A + pair B                       -> mediated result
```

Каждый промежуточный результат обязан сохранить provenance и причину расхождения. Это надо A/B-проверить против текущего ограниченного сложения весов; заранее считать новую схему лучшей нельзя.

### 3.5 Почему ML-runtime пока не подходит

Сам репозиторий фиксирует `Advanced Alpha` и toy-scale: `d_model=128`, 800-1000 шагов и менее 100K токенов; тесты преимущественно проверяют shapes, gradients и локальные математические ограничения, а не качество семантического продолжения на независимом корпусе. См. [README](https://github.com/svend4/pro2/blob/0f897158e1a5f5dda9cedee158733324cf8258e4/README.md#L283-L303) и [IMPLEMENTATION_STATUS](https://github.com/svend4/pro2/blob/0f897158e1a5f5dda9cedee158733324cf8258e4/docs/IMPLEMENTATION_STATUS.md#L127-L171).

Кроме того, [`E2Inference`](https://github.com/svend4/pro2/blob/0f897158e1a5f5dda9cedee158733324cf8258e4/e2_inference.py#L66-L109) создаёт модель до поиска checkpoint и продолжает с ней, если файл не найден. Поэтому этот класс нельзя считать готовым evidence-provider: отсутствие обученных весов должно приводить к `UNAVAILABLE`, а не к выводу случайно инициализированной модели.

## 4. Что не переносить

### Из `meta`

- Solan-кодирование слов как семантическую модель;
- криптографические, биологические и физические заявления без независимой проверки;
- PDF, шрифты, viewer и исходники без лицензии;
- Python subprocess-runtime и mutable JSON context;
- объёмный монорепозиторий как backend P78.

### Из `pro2`

- жёстко назначенные Q6-«доменные якоря»;
- PPL/LCI и внутренние проценты как доказательство смыслового качества;
- checkpoints и `E2Inference` как готовую модель;
- текущий Nautilus-consensus, если он измеряет присутствие источников вместо согласия содержания;
- тензорный `TransactionGate` как замену CAS-транзакциям P78;
- весь training/runtime-монорепозиторий.

## 5. Совместимость с исследованием Рамсея

Q6 и асимметричный оператор из [`24-p78-ramsey-parallels.md`](./24-p78-ramsey-parallels.md) решают разные инженерные задачи:

```text
Q6: какое одно условие изменилось между двумя экспериментами?
D*-подобная асимметрия: в каком направлении допустим следующий смысловой ход?
```

Их можно соединить так:

1. зафиксировать одну Q6-ячейку из шести диагностических флагов;
2. изменить один флаг и пересчитать кандидатов;
3. для каждого кандидата вычислить `P_3D`, `P_1D`, `P_2D_fwd`, `P_2D_rev`;
4. сравнить guard и точное `before/after`;
5. ничего не применять без статуса `READY` и транзакции.

Q6 здесь не является «шестимерным смыслом», а `D*` не является физической двумерностью.

## 6. Рекомендуемый порядок

### Внедрить первым

1. чистый JS-проверяющий автомат жизненного цикла controller/ledger;
2. расширенный паспорт evidence-provider с `ABSTAIN/UNAVAILABLE`;
3. read-only `Stress` для проверки честности 2D-архипелага.

### Провести как изолированный эксперимент

4. Q6-стенд шести измеряемых флагов с изменением одного бита;
5. таблицу вкладов и избыточности источников;
6. попарную медиацию evidence с A/B-сравнением на фиксированном корпусе.

### Не планировать

7. подключение внешнего Python/PyTorch-runtime к основному браузерному потоку;
8. перенос Solan/Q6 как семантической истины;
9. прямое копирование кода до появления полноценной лицензии.

Безопасная точка подключения:

```text
офлайн-эксперимент
-> версионированный локальный JSON
-> evidence provider P78
-> read-only диагностика
-> ограниченный бонус ранжирования или ABSTAIN
-> существующие guard/controller/transaction/ledger без изменений
```

Так из двух репозиториев сохраняется полезная дисциплина эксперимента, но не переносится их неподтверждённая семантика, вес моделей и архитектурный риск.
